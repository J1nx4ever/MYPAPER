# 物料兑现、图/C128 利用与 PPO 后期机制

本阶段承接已完成的同种子学习率比较，保留 **3e-4/u13** 为主要独评基线。先解释调度承诺能否经过运输、服务、卸载和破碎，在截止时间前变成满足生产与品位约束的实际处理物料，再讨论模型改动。

首轮离线研究已完成：20条失败/配对成功轨迹、987个决策前缀及兑现关联、118个真实基态/275个外生分支、512班训练支持、800状态银行，以及3个原后期更新/2212个Minibatch的精确重构。具体早期替代动作的因果效果和后期Checkpoint独立性能仍待新的验证。

本轮只分析封存数据，未启动 AnyLogic、新班次、RPC 或预算登记，未修改 ALP、原学习器或受保护 PPO 核心。结果集中在 [报告目录](../../../../reports/token_attention_001/business_graph_summary_009/next_stage_mechanism_001/README.md)。

2. `interventions.py`：在选定的 118 个真实决策状态上扩展 A/B/C；以封存 3e-4/u13 正常完整前向为主，四种 Graph/C128 组合只用于机制分解。扫描原 512 个训练班次的 93,534 个决策，核对有限组业务变量的边际支持；`joint_support.py` 进一步检查与干预相关的离散联合模式。
3. `late_updates.py`：在旧 u13 的 100 班独评中，固定每窗决策序位 25%/75%，构成 800 状态银行，比较 u10–u16 的策略与 Critic。此银行不按成败筛选。
4. `minibatch_replay_v2.py`：从封存原状态和原批次，在内存副本重构 u13→u14、u14→u15、u15→u16。使用原学习器数值路径、原2线程设置与原私有 shuffle RNG；只增加 detach/no-grad 观察器。要求优化前冻结目标、最终 Actor、Critic、Adam、目标、RNG 与原封存下一 Checkpoint 逐项一致。重放的内存优化步与新增正式训练严格区分，不保存新的模型。

数值重构身份、配置字节 SHA、96 个历史 run/seed、来源封印与输出目录见 [minibatch_replay_config_v2.json](minibatch_replay_config_v2.json)。首轮误用1线程而非原2线程，未通过一致性验收，其脚本/配置/拒绝记录保留，指标不采信。这是历史更新重构，新的 recording_id、run/seed、AnyLogic 事件目录均不适用，不需要用户操作仿真端。

原运行依赖模型、Adam、私有随机数状态和数值环境共同确定更新路径。不能只恢复相同seed和模型权重就将新计算称为原更新。Minibatch详细统计仅在本次定位问题的隔离内存副本中读取，不启用真实训练的逐transition/请求/全量观测记录。

## 证据分级与下一步判定

### 物料兑现

- **条件性排除**：在真实决策前缀，保持已有 FIFO，按固定 work-conserving 破碎能力计算强制处理前缀；即使剩余容量允许不限量、瞬时到达、品位任取 `[0,1]` 的物料，最终品位范围仍不与 `[0.26,0.28]` 相交，才能给出该假设下的不可恢复证据。
- **尚未排除**：乐观范围与合格范围相交，只能定位值得检查的更早决策，不能解释为可兑现机会。第一个已观测到排除的时刻不是精确失效时刻。
- **策略漏选已证实**：需要具体合法替代动作及吨位，在当时可用资源下贯通运输、排队、装载、卸载、FIFO 处理，证明截止前实际处理量/金属量改善；还要检查后续窗口、矿废达产及等待代价。

当前日志缺 `LOAD_COMPLETE`，不能从相邻决策或未来卸载倒填精确装载完成时刻、当时未知品位或历史来源。事件序号作为屏障；未来物料事件只用于结果解释和守恒核对。

下一次需要仿真的研究，应先明确状态分支/恢复能力和外生随机量的配对口径。仅“相同总 seed”不足以保证替代动作后仍使用相同外生条件：动作可能改变随机数消耗次序。应检查车辆行驶、服务、物料块等随机源如何绑定，随后才准备独立身份、预算和手工设置卡。本目录没有授权或启动这类新班次。

### 图与 C128

A 是已知装载完成后的内部瞬态；B 是非决策车辆未开始服务的预留重定向；C 是当前破碎能力减半。三者都是从真实状态构造的外生分支，均未实际仿真。A/B 必须满足服务、账本、路径和数量约束；不适用的状态记为不适用，不能强行套用旧单快照构造。

图/C128 的 Shapley 分解包括完整正常分支、仅换图、仅换 C128 及基态。Mask 和候选吨位保持一致；图贡献含 GNN 与确定性图数量通道。贡献反向只表明该输出上的相抵，不表明哪一支正确。概率改变不等于调度质量提高。

边际支持扫描给出十组业务量的范围和百分位。A/B 在边际范围内不能证明联合分布覆盖充分；C 的 1250 tph 明确超出原训练恒定 2500 tph 的参数支持。若要将“覆盖不足”确认为原因，需要新增匹配训练覆盖/消融实验，不能只从弱响应归因。

进一步的有限联合模式检查发现，A的53个分支都包含训练决策中未见的“已载矿＋OTHER阶段”；B的57/104分支的“TO_LOAD＋目标＋当前段＋有序路线”模式未见。其余B模式出现过也不足以证明完整状态支持。下一轮要优先验证正常决策时刻可达、并有训练覆盖的干预。

### PPO 后期机制

区分三种量：Minibatch 的更新前采样反向 KL 近似、epoch 末完整原批次 KL、固定状态银行的精确分类分布 KL。Critic EV 与目标方差、MSE 共同解释；Minibatch EV 小样本波动不能代替完整批次 EV。

数值重构只有在封存终点完全一致后才采信，且标注为“重构”，不能伪称原运行实时保存的日志。后期策略移动和训练批次成本变化不能直接推出独立性能下降。对应 u14/u15/u16 的固定 Checkpoint 独评仍是下一次需独立身份与预算的验证任务；本轮不扩大物理实验。
