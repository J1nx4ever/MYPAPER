## 保存模型的计算路径

| 检查项 | 结果 |
| --- | --- |
| 矿废属性和卸点 | `Main.init1` 在生成矿块前读取四站的 ore flag、均值和半区间。装矿时载荷继承实际站点类型。卸料回调要求当前卸点与目标匹配，矿石走破碎站，废石走接废卸点。错送、废石带金属或超班末载荷会由回调拒绝或排除。 |
| 矿块抽样和装载品位 | 用保存模型中的矿块生成、装载和库存更新函数，在隔离 Java 中测试冻结表的 33 个工况。独立随机流与 7,920 个实际函数生成的块值逐个一致。24,684 笔装载按地质区间重叠吨位重算，其中 7,788 笔跨块，品位、金属量、库存扣减一致。 |
| FIFO 与窗口品位 | `advanceCrusherTo` 按实际物理时间与破碎速率消费首批，跨边界时分段。窗内累计 `Q=Σq`、`M=Σ(q×g)`，结算品位为 `M/Q`。用保存模型中实际 Java 函数体和项目的 `WindowSummary` 启动隔离测试，8 个窗口结算全部通过。覆盖边界入料、FIFO 跨窗、空窗、26% 与 28% 临界值，以及班末 FIFO 留料。 |
| 班末平衡与合规 | Java 的物料审计检查采出、在途、卸点实收、FIFO、实破吨位与金属量。空窗判为不合格。四窗品位合规、整班实际破碎 ≥16,000 吨与实交废石 ≥4,000 吨共同决定完整任务。 |
| RPC 奖励和 BG128 成本 | RPC 旧奖励由 Python 校验。BG128 使用真实窗口品位另算训练成本，偏差在 0.004 内成本为零，超出后按 0.006 定标并封顶到 2。整班矿废短缺采用 8/8 系数，车辆等待按累计车秒的增量计算。 |

## 历史闭环复算

对上一轮泛化的 600 个真实 AnyLogic 班，核验账本及封存文件，按 Java 紧凑日志中的实际处理事件独立重算，并逐窗比对原 RPC。

| 核验项 | 结果 |
| --- | --- |
| 派车时刻与 RPC | 109,016 次一致 |
| 破碎站入仓来源与该车最近一次派车 | 81,155 笔一致 |
| 实际破碎事件与窗口 | 178,362 笔归入 2,400 窗 |
| 独立窗口吨位复算与 RPC 最大绝对差 | 约 `4.02e-9 t` |
| 独立窗口金属量复算与 RPC 最大绝对差 | 约 `1.16e-9 t` |
| 终班矿废、等待、成本及完整任务判定 | 全部一致，600 班中 500 班完整任务成立，100 个失败班均来自纯品位互换 |

历史实跑的内部边界用例也显示，14,400 秒实际入仓的载荷对第二窗贡献为零，第三窗加工约 91.7 吨。班末用例在 28,800 秒排除新卸料，已有 FIFO 仍处理到截止。这些证据支持原品位互换失败是真实闭环产物，窗口累加或报表计算错误无法解释超限。[原泛化结果](../paired_generalization.md) · [内部边界 B1](../../../../boundary_supplement_002_B1_review/review.md) · [班末边界 B2U](../../../../boundary_supplement_002_B2U_review/review.md)

原换位首班 `9991101` 首窗独立复算矿石 `4,001.708677 t`，金属 `1,509.825556 t`，物理品位 `37.7295%`，超过 `28%` 上限。原始 RPC raw grade reward 为 `−1`，该窗 BG128 品位成本为 `2`。班内原始破碎记录、业务违规判定和训练成本三者一致。

## 混合活动实跑验收

历史 600 班的废石站均为 Load3。启动混合活动后，从首批实际运行核对发生过的新场景路径。每班应正常结束并给出 `[MATERIAL_AUDIT_PASS]`。在废石位移班确认当班废石站实际产生派车、废石实交和停派账一致，并确认当 Load3 出矿时，有来自 Load3 的实际破碎站入仓/加工记录。紧凑日志只逐笔记录破碎站物料，废石实交由 Java 卸料守卫、卸点实收守恒与 RPC 废石账共同验收。各条路径的通过证据来自确实走过该路径的班次。
