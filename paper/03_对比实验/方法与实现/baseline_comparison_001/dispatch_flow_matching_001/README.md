## 最佳路径与状态初始化

1. 解码有向路网、限速和开放状态。按空载及重载计算最短时间矩阵。首版使用现有可见性和名义车速，当前在途车按可见剩余路程及车速估计。对已知不可达的路段和卸点关闭相应路径。
2. 以 `r=(k,o,l,d)` 表示车型、空车起点、装点、固定卸点。班初车源来自各车可见停车位置及放行依赖。已在装、运、卸的车辆预计在当前任务完成后才回到对应卸点车源。空车可从上一趟矿石或废石卸点去本次任一兼容装点。
3. 建立已承诺车和既有矿批的名义事件回放。产出各车预计再派时刻及节点、铲和卸位占用、卸载预约、入仓和出料，以及各窗的矿吨和金属吨基线。仓内原 FIFO 顺序固定。铲排队、卸位和仓容队首分别建账。结束的品位窗从余班规划中退出。

## 路径流量 LP

决策列 `j=(r,p)`，其中 `p=[a,b)` 是一个派车时段。令 `x_j≥0` 为预计在该段派出的吨位，目标流率为 `x_j/(b−a)`，预计车次为 `x_j/q_j`。其中 `q_j` 为该车型按可见供给计算的单车载量。首版开发参数为近端 30 分钟按 5 分钟分段，远端按 15 分钟分段，时段边界包含当前时刻、各品位窗界和班末。这是连续计划，实时匹配使用观测给出的整车或部分载荷。

### 派车、预约和加工系数

每次重规划先回放既有承诺。对每条有效路线及派车段，在同一份承诺状态上以该段的代表性派车时刻估计一趟边际运输。从已开放路线和已承诺资源日历估计到铲、装完、到卸点、取得卸位、仓容准入、卸完、再派及矿石加工。首版使用等长的三个子段及其中点估时。各子段内按均匀派出，将中点估出的事件时差和矿批加工曲线平移，按子段长度加权。以此得到固定的累计比例曲线。

| 系数 | 截至时刻 `t` 的累计含义 |
| --- | --- |
| `D_j(t)` | 已派出的比例 |
| `V_j(t)` | 矿车已获得整车仓容预约的比例 |
| `U_j(t)` | 已完成卸载的比例 |
| `H_j(t)` | 车辆已可在目的卸点重新派出的比例 |
| `C_j(t)` | 矿石已破碎的比例，按实际品位窗边界切分 |

矿石列满足 `0 ≤ C_j ≤ U_j ≤ V_j ≤ D_j ≤ 1`，所有列满足 `H_j ≤ U_j`。在预测仓容准入前完整计入卸位占用。仓容预约在卸完时释放，并等量转入 FIFO 实物库存。已承诺预测与新增边际列各记一次。边际列共享实际资源，LP 的叠加系数属于聚合近似。任何候选计划都以同一组已冻结系数求解和复核。 [现有 FIFO 事件顺序](../../../../../traditional_dispatch_v1/nominal.py#L395) · [V3 归窗系数参考](../dispatch_fifo_v3_001/v3_flow.py#L42)

### 约束与目标

- **车辆守恒。** 对每个车型、起点和时间节点，累计新派车次 `Σ D_j(t)x_j/q_j` 不超过该起点的初始可用车、既有任务的累计可再派车辆和新计划中卸回该点的累计车次 `Σ H_j(t)x_j/q_j`。新任务按正的循环时差回流。车型、铲和卸位另受各区间可用时长限制，区间行先扣掉既有承诺占用。
- **资源与库存。** 总派出吨位受各装点可用库存约束。矿石在仓质量为 `B(t)=B₀(t)+Σ(U_j−C_j)x_j`，预约为 `R(t)=R₀(t)+Σ(V_j−U_j)x_j`。要求两者非负且 `B+R≤仓容`。区间新增破碎量与既有破碎量之和受该区间破碎能力约束。约束代表核验网格上的预测聚合占用。
- **废石与班末。** LP 的新增废石派出额度以实时承诺量距停派阈值的余量为上限。实时层使用实际动作掩码和条件性整车超额规则。废石产量使用班末左极限 `U_j(T⁻)`，矿石加工积分到 `T`。班末恰好卸完的废石车结算到班外，已经在仓的矿持续加工至班末。
- **品位与产量。** 对每个未关窗，`Q_w=Q⁰_w+ΣΔC_{j,w}x_j`，`M_w=M⁰_w+Σg_jΔC_{j,w}x_j`，其中 `ΔC_{j,w}` 是该窗内的加工比例。加入 `0.26Q_w−s⁻_w≤M_w≤0.28Q_w+s⁺_w`、班末矿废下限和各窗供料行。为避免空窗在线性品位式中自动可行，规划设置最小车型载量的软供料目标，正式结算仍以窗口有矿及品位区间判定。

两阶段求解。第一阶段最小化归一化业务缺口之和，再在锁定第一阶段最优值的容差内最小化所需车秒 `Σ T_j x_j/q_j`，其中 `T_j` 为该列预计从派车到再派的平均秒数。初始缺口归一化尺度为矿废各自班目标、每窗 `0.01×(矿石班目标/窗数)` 金属吨、最小车型载量供料吨。资源和车源为硬约束。窗口、缺口和资源使用以原单位发布，便于复核。发布前复验实际非负向量的约束残差。第一阶段时限内得到经复验的可行解但未证明最优时，或第二阶段超时时，可发布经复验的第一阶段解，同时分别记录可行状态和已完成的求解阶段。 [现有规划约束](../../../../../traditional_dispatch_v2/flow_plan.py#L255)

## 实时路径匹配

### 需求时刻与损失吨

计划版本 `v` 从时刻 `t_v` 生效。对路径 `r` 积分分时流率得到累计目标 `F_r^v(t)`，`A_r^v` 为本版本已确认的派出吨位。下一车需求时刻为 `τ_r=inf{t≥t_v : F_r^v(t)>A_r^v+ε}`。仍有效的逾期需求保留其原时刻。计划用尽或零流量的路径取无穷。品位窗关窗或计划因设备状态失效时，先处理重规划，再用当时仍有效的余班目标选车。

每次匹配包含当前车及预计最早可再派的至多两辆车。对尚未分配的车，逐次处理最早需车且有合格候选的路径。当前车必须符合实时掩码，预测车使用其预计位置、载重和名义合法性。只在计划有效时段内接受候选，含同派车段内的提前量以及仍有效的逾期需求。对最缺路径，比较把各车插入资源日历后产生的损失吨。

```text
损失吨 = 车型参考吨率 × 额外空驶秒
       + Σ车辆 (车型参考吨率 × 增量等待秒)
       + Σ有有效流量需求的铲 ∫ 计划吨率(t) × 增量闲置铲位(t) / 铲总容量 dt
```

车型参考吨率为该车型载重除以其当前开放路径的最短名义循环秒，单位为吨/秒，同次请求内固定。额外空驶相对该车最短合法空驶。等待与铲闲置在当前时刻至未来 30 分钟或班末的较早者，用同一基础日历做插入前后差值，包含受影响的已承诺车辆。铲闲置减少可以减少损失。候选使用同一局部日历估计等铲、卸位及仓容等待。并列时依次按预计可派时刻、车辆 ID 和路径键。匹配后只更新临时的流量账、资源日历和候选车集合。当前车取得动作即提交。 [公开需求时刻与损失吨](https://patents.google.com/patent/US20090096637A1/en#:~:text=LostTons) · [现有车铲日历](../../../../../traditional_dispatch_v2/dispatch_policy.py#L71)

### 超配、重规划和回执

- **强制派车。** 路径已覆盖或当前时刻没有有效配额时，优先选择仍有可接纳余量的合法路径，再按损失吨排序。以当前派车段的系数将超出有效配额的部分加入计划剩余量，检查资源上限及品位、产量松弛是否增大。若所有合法路径均超出计划余量，在实时掩码内按同一损失吨规则选择，登记实际超配吨并申请重规划。单一合法动作直接返回并按同一口径记账。
- **重规划。** 首次请求、距上次成功计划 900 仿真秒、品位窗切换、道路或装卸设备可用状态改变、废石停派状态改变时重算。无配额而超配，或同一未结算窗的预计破碎吨相对现行计划偏离至少最小车型的一车载量时，也申请重算。后两种软触发由 120 仿真秒的最小间隔合并，状态变更触发优先。
- **执行与恢复。** 先用可见 ETA 与队列形成一个确定性的合法备用动作，再使用共同的绝对时限规划和匹配。工程初始目标为规划总预算 800 ms，RPC 收到至响应 1,000 ms。求解失败时仅复用经当前配置、拓扑、合法掩码与有效期复验的计划。匹配超时使用已完整计算并复验的当前车动作。没有可用计划时使用备用动作。掩码全空由现有 RPC 契约报错并保留异常回执。
- **台账。** 以 `recording_id`、请求序号及回显动作做幂等确认，将真实派车的可核对预留吨记入 `A_r^v`，预测车辆只写临时账。切换版本时，把旧任务放进新计划的既有承诺和资源占用，令新版本新增派出账从零开始。跨版本流量误差按每段实际生效计划累计，矿吨和金属吨以物理结算独立累计。 [现有 RPC 回显确认](../../../../../traditional_dispatch_v2/runtime.py#L145)

```text
收到派车请求，核对配置、观测和掩码
计算合法备用动作并确定本次截止时间
若触发重规划，回放既有承诺并求解路径流量 LP
以有效计划和临时派车账，按需求时刻与损失吨匹配
若当前车没有匹配，按补充分配规则选合法动作
复验并返回当前车的动作，保存待确认的路线和预留吨
收到该动作回显后确认派车账，班末以 END 结算物理量
```
