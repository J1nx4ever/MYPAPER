# BG128 论文的运筹基线设计

## 两组在线 MILP 的首轮实现

- [滚动整数配额与 Policy4 追踪](rolling_quota_policy.py) 从班前 48 项配额起步，按周期和记账窗切换重算剩余整数车次。上层用已承诺批次的 FIFO 回放和名义资源系数估计真实窗口出料。发布配额时加入已确认车次，收到真实动作回显才计下一车。车型在时段内用集总车时约束，逐车归窗及产量由闭环评价。
- [车次级 FIFO 滚动 MILP](trip_fifo_policy.py) 联合选择近端具体车辆的装点、装卸及破碎预约。服务与仓容约束由同一 MILP 检查，破碎吨按固定窗切分。远端供料来自冻结的名义续派。再从原快照用连续时间事件模型验证动作序列和业务代价，实时只发当前车的装点。近端车辆、预约时刻和远端续派是开发版的近似边界，求解间隙限于该预约模型。

[离线验证入口](review_milp_offline.py) 对三个历史班次已封存的每窗首末观测做 24 帧核对，检查合法动作、求解结论和确认计数。共同续派到班末的结果是单个首动作的名义诊断。配额模型在隔离帧上单独启动求解以检查整数模型，实际策略从班初逐车累计的配额台账由闭环验证。 [离线验证报告](../../../../../reports/token_attention_001/business_graph_summary_009/baseline_comparison_001/or_paper_comparison_001/milp_offline_review_001.json)

[AnyLogic 两班试跑](manual_anylogic_milp.md) 每组先跑一班，使用一个新的共用标称环境种子。核对首帧与实际 RPC、真实动作回显、两组 MILP 解的使用及 1 秒 RPC 响应，再查四窗品位、矿废实绩、联合成本和回退原因。根据两班的实测结果确定后续班数和参数冻结版本。

两组各十班的测试使用 [十槽配对启动包](paired10_001/manual_anylogic.md)，沿用已通过离线核验的策略设置。旧两班包保留原配置和身份。

品位控制版 DISPATCH 和滚动配额 MILP 与原 100 个标称槽的对比，使用 [两组百槽启动包](paired100_strong_001/manual_anylogic.md)。从原始 baseline 文件接入时，先按[原件兼容清单](paired100_strong_001/alp_audit.md)核对工作副本。

## 原论文对比设计

三组 MILP 的变量、约束、计算步骤及待审参数见[数学定义](mathematical_spec.md)。

主表为 **三组 MILP、DISPATCH-inspired FIFO V3、多步滚动搜索和冻结 BG128**，共六组。三组 MILP 覆盖班前固定整数配额、在线更新整数配额和具体车辆的短期联合排程。DISPATCH-inspired FIFO V3 代表连续吨流指导与多车匹配，多步滚动搜索代表基于事件回放的有限深度优化。固定配额的 FIFO 前瞻版用于预测与评分机制消融，卸载贪心与 FIFO 贪心可列在附录。 [FIFO 机制消融](../policy4_fifo_comparison_001/README.md)

| 主表组别 | 优化变量与频率 | 交给 AnyLogic 的动作 |
| --- | --- | --- |
| 固定车次 MILP＋Policy4 | 班前求一次各窗、各类型、各装点的 48 项整数车次。复用已冻结计划，保存解与 ALP 已逐项对齐 | 原生 Policy4 追踪派车；名义 FIFO 信号、900 秒提前换配额窗仍参与评分 |
| 滚动配额 MILP＋Policy4 | 班初共用原 48 项。按预先固定的周期和窗口切换触发，只重求余下未派车次的整数配额。保留当前资源及既有承诺 | 使用同样的四级 Policy4 跟踪。每次更新把剩余配额与已派账合并为追踪目标 |
| 车次级 FIFO 滚动 MILP | 每次派车时求当前及近端几辆车的装点、资源和服务顺序，远端用余窗产能和产量约束。已派车作为初始承诺 | 提交首辆当前车的合法装点，其余作为预测；下一事件据新观测重算 |
| DISPATCH-inspired FIFO V3 | 用滚动 LP 求连续目标吨流，提名多车组合，再用 FIFO 回放筛选 | 提交筛选出的当前车装点。原 100 槽已完成 |
| 多步滚动搜索 | 通过名义事件模型枚举短动作序列。正式设置为深度 3，最多扩展 20 个节点 | 提交短序列的首动作。原 100 槽已完成 |

## 滚动配额 MILP

用当前 1519 维物理观测预测已派车及在仓物料的未来出料和资源占用。上层变量为剩余派车时段 h、类型 k、装点 i 的整数 `x[h,k,i]`。余窗约束先计已破碎的实测量与预计仍会完成的既有承诺，再计新增车次；新车次到期出料按可见条件估计。运输、铲、卸位及破碎周期占用扣除既有承诺后使用剩余能力，供矿与废石限制取实际 RPC。窗口缺口与过量兼顾；没有可行零缺口解时显式报告松弛。该上层以集总粒度估计新增车次，逐车真实时序由 AnyLogic 演化。

更新配额时，已经派出的车不可重指派。新解同时保留派车账和物理量账。派车账以原配额窗的已派次数加该窗剩余新车次作为新追踪目标，既有车次只出现一次。质量与库存账按预计卸载和破碎时间记，禁止用派车记账窗替代真实质量窗。第一版宜在窗切换和班中预设周期重算，例如 15 分钟。配额窗切换规则沿用 Policy4。求解失败时保留上次可用配额，写入汇总。

## 车次级 FIFO 滚动 MILP

采用时间离散的车辆资源排程。二元变量 `x[k,i,tau]` 指定车辆 k 在候选可派时段 tau 选择装点 i。近端包含若干有预测可派时刻的车辆、装卸资源占用、整车卸载预约、FIFO 顺序与处理量；日程须保持车辆因果顺序。模型仅在同一动作接口允许的装点间选择。当前车辆必须在本次真实请求返回动作。模型中的服务排队由物理资源触发。

初期可在开发数据上检验 30–45 分钟近端范围，余下品位窗接续班末产量与可达性约束。近端和远端之间传递边界库存、批次顺序、吨金属量、在途及预约，不把短视界末的未破碎吨位当成已产。以分时约束缩小优化模型，提交前在同一名义事件模型中复核整车预约、FIFO 顺序和固定窗结算；任何离散近似造成的偏差按复核结果处理。全部预测使用请求时已观测状态、现场已知常量与预先冻结的未来品位和行驶估计。

对批次 b，预测卸完时刻是 `u_b`，FIFO 加工开始时刻按队首可用时刻及该批入仓时刻取较晚值。入仓时序由卸载与资源排程给出。加工区间为 `[s_b,s_b+q_b/r)`，处理速率 `r = 2500/3600 t/s`。窗 w 的矿量 `Q_w` 和金属量 `M_w` 来自批次加工区间与该窗相交的吨位。卸位获得后检查 `库存 + 已预约 + 当前整车载荷 ≤ 500 t`，卸完才转入 FIFO。 [现有名义仓容和 FIFO 事件模型](../../../../../traditional_dispatch_v1/nominal.py) · [露天矿整数排程文献](https://optimization-online.org/2020/02/7646/)

计划先减少品位和产量缺口，然后比较预计品位偏差与等待。可用金属吨松弛 `s_w^-, s_w^+` 写成 `0.26 Q_w − s_w^- ≤ M_w ≤ 0.28 Q_w + s_w^+`。矿石全班破碎量至少 16000 吨、废石全班实际卸达至少 4000 吨，用吨位缺口表征不可达状态。真实评价把空窗记为未达标。用已完成的合法计划热启动，记录最优界、可行解差距、实际回退和响应耗时。800 ms 可作为与现有优化基线对齐的在线规划预算初值，最终由开发槽和闭环联调核验后冻结。候选、回退和预处理的 CPU 时间均纳入端到端延迟说明。

## 比较和验收

- 使用同一九车 AnyLogic 物理工况、四装点、同一 1519 维观测和合法动作掩码。业务废石门槛为 4000 吨。若复用已有标准槽，三组运筹一律沿正式工况已承诺废石 6000 吨停止规则和 6193 吨超额上限。
- 跨策略逐槽核对环境种子、真实 RPC 物理契约、初始观察和首车。策略专属的 RPC 身份与共同物理字段分别严格校验。原生 Policy4 在 Java 选择，Python 验证动作提案和回显；滚动求解放在 Python。既有原生离线入口绑定高频日志，正式使用专用低频评估适配。保留 BG128 的冻结 checkpoint 与原采样协议。
- 首先用历史决策帧及合成边界对账，然后进行新身份的单班闭环和少量开发槽，最后冻结求解参数、预算和回退规则。标准工况 100 个配对槽为主结果。冻结 BG128、多步滚动与 V3 的 100 个槽已查实种子、首帧和实际 RPC 一致。三组新 MILP 通过相同契约核验与种子复用登记后，各新增 100 班，主表共 600 个策略班次，按标准工况的配对补测报告。采用独立未查看种子时六组各运行 100 班。 [V2 五组封存](../../../../../reports/token_attention_001/business_graph_summary_009/baseline_comparison_001/paired_v2_100_001/paired_comparison.json) · [V3 封存](../../../../../reports/token_attention_001/business_graph_summary_009/baseline_comparison_001/dispatch_fifo_v3_002/dispatch_fifo_v3_evaluation.json)
- 论文主对比预先指定 BG128 与车次级滚动 MILP，以每槽联合成本差及 95% 配对区间报告，同时给出完整达标率、四窗吨位和品位、矿废产量、三类等待、响应耗时、可行解差距与回退。固定对滚动配额用于比较同一追踪器下两套计划机制。若要单独归因于重算频率，须使用同一上层预测、目标和约束，只比较班前一次求解与班中多次求解。所有正常完结班次都计入业务结果。若论文还主张扰动适应能力，在已选定的速度扰动或减车工况上以同种子复核主对比并另表报告。

本方案规定策略与实验设计。物理启动前另需冻结逐班 run、recording、配置字节 SHA256 及输出路径。实际预测质量和求解时限将在闭环验收中判定。
