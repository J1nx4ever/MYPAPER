# Policy4 的 FIFO 前瞻对照方案

本方案是同一固定计划下的 **Policy4 FIFO 机制消融**。原生 Policy4 与 FIFO 前瞻版的同槽差值估计替换派车品位预测与评分模块的收益。主论文比较采用三组 MILP、DISPATCH-inspired FIFO V3、多步滚动搜索和冻结 BG128。 [主论文运筹基线](../or_paper_comparison_001/README.md)

## 原生策略与输入来源

班前 Python 用 `x[w, site, type]` 表示每窗各车型到各站的整数车次，最小化名义运输周期车分钟。每窗矿石 4000–4100 吨、废石 1000–1200 吨、均值品位 26.9%–27.1% 是班前计划的筛查条件。车型时间、铲、卸位、破碎机产能和储量同样以汇总条件建模。已核对 ALP 的 `planTrips[w][type][site]`、JSON 和 CSV 的 48 项整数完全一致，四窗分别安排 36、35、33、34 车。实验使用这份固定表。 [班前求解器](../../../../../../../policy4/v4_python_projection/ore_waste_parameters_v1/verify_parameters.py) · [计划与数值见证](../../../../../../../policy4/v4_python_projection/ore_waste_parameters_v1/参数设计与前置验算.md) · [ALP](../../../../../anylogic/3d/DRL-PPO-baseline1/DRL-PPO-baseline1.alp)

原生 Policy4 每次先将破碎机和品位窗同步到当前仿真时间，用 `min(3, max(physicalWindow, floor((t+900)/7200)))` 选计划窗。已在仓内的矿按 FIFO 拆到当窗和次窗。仓外已承诺矿中，已装载用可见实际品位，未装载用装点名义品位。选择当前计划窗时，以“已破碎＋仓内当窗增量＋0.35×仓外矿”估计品位。选择下一计划窗时，用“仓内次窗增量＋0.65×仓外矿”。仓外权重是分窗代理。

依次优先本车型本站剩余配额、跨车型本站总剩余配额、矿石品位纠偏、SQ 回退。前两级的站点分数为剩余配额比例减 `0.15 × 活跃车辆数` 加品位修正。第三级将当前待派载荷加入品位代理，按距 27% 的绝对差及 `0.10 × 活跃车辆数` 评分。分配选定后只增加 `assignedTrips[planWindow][实际车型][选定站]`，支援其他车型也如此。实际破碎窗由物理事件确定。 [ALP 派车、统计与原生 RPC 分支](../../../../../anylogic/3d/DRL-PPO-baseline1/DRL-PPO-baseline1.alp)

主目录 `project_fifo_only` 可作为仓中物料积分的独立校验。正式 1519 维 RPC 直接提供 FIFO、已承诺车、排队和路况等状态。BG128 的 C128 已用到基于当前信息的名义到达、已承诺 FIFO 预测与候选 ETA。两组的可比问题是如何用预测做派车。 [仓内 FIFO 积分](../../../../../../../policy4/v4_python_projection/python/window_projection.py) · [BG128 观测摘要来源](../../../../../grade_commitment_ppo_v1/features.py)

## FIFO 前瞻版的决策

两组 Policy4 使用相同的 48 项表、900 秒计划窗切换、配额记账、阶段顺序、各阶段合法候选集合、活跃车辆惩罚和原有并列顺序。FIFO 版在首个有合法候选的阶段比较当前车的每个动作。班中只优化当前动作，计划表在整班固定。

以同一 1519 维快照复制预测状态。分支 0 仅推进已承诺运输，分支 a 加入当前动作 a。所有分支推进至次窗结束或班末，不加入其他未发令车辆。已在 FIFO 的批次、已预约但未卸完的车、在装卸资源或在途的车按实际阶段各计一次。已知品位用观测值，未知品位用该点当前可见均值。空驶、铲服务、重驶、卸位排队及仓容等待采用同一名义事件模型。整车获得卸位且仓存、预约吨位与该车载荷合计不超过容量后才能开始卸载，卸完后入 FIFO 尾部。既有 FIFO 顺序不可更改。 [名义事件、仓容与 FIFO](../../../../../traditional_dispatch_v1/nominal.py)

在同一矿批的预测出料区间内，按实际窗边界切吨。对矿批 b、出料区间 `[s_b,e_b)` 和统计窗 W，窗口质量为 `q_bW = r × length([s_b,e_b) ∩ W)`，金属吨为 `q_bW × g_b`。当窗已有实测矿吨和金属吨加一次。已卸车尚未在班内破碎的矿不计当班矿产。计算候选分支合计品位，允许某动作推迟其他批次，把其造成的变化一并归入候选差值。

首版候选评分以 27% 为中心，沿用 Policy4 的 1000 吨置信量纲和两个品位尺度。令 `D(a) = sum_w abs(M_w(a) − 0.27 Q_w(a)) / max(1000, Q_w(a))`，只对当前与次窗求和。无候选分支记作 `D(0)`。空窗在部分预测中提供零品位信号，班末评价仍判空窗未达标。

| 阶段 | FIFO 版评分 |
| --- | --- |
| 本车型配额或同点总配额 | 原剩余配额比例 `− 0.15 × 活跃车辆数 + 1.50 × clip((D(0) − D(a))/0.025, −1, 1)` |
| 仅矿石纠偏 | `−D(a)/0.01 − 0.10 × 活跃车辆数` |
| SQ 回退 | 原生 SQ |

前两阶段的废石候选也参与反事实预测。废石没有直接矿石品位项，但其名义动作若改变已承诺矿批的出料则反映在 `D(a)`。当前名义资源模型的矿废卸点独立时，该品位变化为零。全部候选需要完整对照才使用 FIFO 排序。超时或分支模型异常时使用同一决策的原生等价首选，分别记证据。单候选直接选择，汇总记录每阶段可选数量，以量化 FIFO 评分实际有机会改派的比例。虚拟分支不写真实配额。真实动作由 AnyLogic 回显确认后，Python 配额账本只更新一次。

上述方案检验的是**显式 FIFO 预测和相应评分模块的联合效果**。如果后续要把预测精度与评分设计拆开，可在同一批历史观测上为两种投影使用同一个评分函数，逐动作复算排名。该离线比较用作机制诊断，主实验的实际指标仍从仿真 END 结算。

| 项目 | 配对设计 |

| 物理启动 | 原生组在 Java 选择，Python 只验证提案、48 项表和动作回显。现有 `offlineNativeCollection=true` 依赖高频 boundary 记录，正式需单独的低频原生评估分支。FIFO 版与 BG128 走 Python 决策 RPC，复用默认低频采集。原生评估分支需独立配置字段，由收集器逐组核对策略身份并按共同物理字段配对，任何缺失或额外字段按声明规则处理 |
