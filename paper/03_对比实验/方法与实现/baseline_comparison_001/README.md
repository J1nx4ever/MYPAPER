## 0. 研究尺度约束（来自立项书 V1.0 §1）

单个 8h 班次 = 一次独立 AnyLogic run，独立初始化，**破碎仓存货与未兑现承诺不跨班继承**；4 个 2h 品位窗为硬约束；9 车 / 固定拓扑 / 固定观测合同。因此：

- 基线只能是**班内**方法，时域 H ≤ 班末 28800 s。
- 论文写 **intra-shift rolling optimization**，不写 "rolling horizon optimization"。
- 任何跨班配矿计划、跨车数基线均属 future work，不进本文对照。

## 1. 设计铁律：所有基线必须跑在同一条链路上

基线**不做成 AnyLogic 内部控制逻辑**，而是**策略适配器**，与 RL Actor 同槽位替换：

```
AnyLogic ──gRPC──> RPC 服务 ──> 观测 (B,35=1519D 快照压缩) + prefixes(C128) + action_mask
                                      ├─ RL:   BG128 Actor → logits(4) → 采样/argmax
                                      ├─ B1:   规则打分 → argmin
                                      ├─ B2:   班内滚动 LP → 目标流量 → 兑现器 → 动作
                                      ├─ B3:   静态分配表 → 查表 → 动作
                                      └─ B5:   品位目标贪心 → argmin
```

只有这样三/五组才能**逐槽复用同一批评估种子**，差异才归因于决策规则而不是随机数消耗顺序。任何"改 AnyLogic Dispatch 逻辑"的做法都会破坏配对，不采用。

**约束**：不改 `episode_budget_ppo.py`（SHA `8e4cfa31…`）、不改观测契约、不改 4×2h 窗品位判定、不改 episode 终止条件。

## 2. 基线清单：四类 + 一个上界

| 层 | 基线 | 作用 | 预算 | 必需性 |
|---|---|---|---|---|
| L0 下界 | **B1 纯反应式**（ETA + 队列） | "现场不做配矿"的失败下界；同时是链路验证 | 100 班 | **必须** |
| L0 下界 | **B3 静态固定分配**（Layer 1 车铲匹配表） | 用你自己的静态匹配理论给出 N_j→车组的固定分配，是"理论最优的静态方案" | 100 班 | **强烈建议** |
| L1 工业规则 | **B5 品位目标贪心**（配矿员逻辑：按窗目标品位选装载点） | 现场"配矿工程师"的实际做法，比 B1 聪明但无前瞻 | 100 班 | 可选 |
| L2 运筹优化 | **B2 班内滚动 LP + 兑现器** | 主线对手：同信息、同结算、有约束规划 | 100 班 | **必须（gate）** |
| 上界 | **B4 离线全知 oracle** | 用实测轨迹事后求 LP，给"完美信息"上界，衡量 RL 距最优多远 | **0 班（纯离线计算）** | **强烈建议** |

**B4 是性价比最高的一条**：它不跑 AnyLogic，直接用已有 700 班独评日志里的实测 ETA / 服务时间 / 品位，离线解一个确定性配矿 LP，得到"如果预知一切，最多能做到多少"。审稿人必问"你离最优多远"，没有 oracle 这条答不上，而它几乎零成本。

**B3 的额外价值**：它把你的 Layer 1 静态匹配理论直接变成对照组，论文里可以写"静态最优 → 班内滚动 → 学习型策略"的递进，比只跟规则比更有分量。

**不需要的**：不用再单列"旧 u32 检查点"或"无图 MLP"作基线——它们已经在 7 工况配对评估与结构消融里，重复列入会让对照表臃肿。

## 3. 各基线的精确定义

### B1 纯反应式（reactive-greedy）

```
score_j = ETA_i,j(名义) + queue_j × t_srv(j) + M·[j 不可用]
选 argmin_j，同分按最小 index 决胜（完全确定性）
```
禁止使用 `grade_mean/std`、窗内已累计品位、任何未来量（C128 的 88–127 维候选摘要全部屏蔽）。策略零随机，靠环境扰动取样。

### B3 静态固定分配（static assignment）

用 Layer 1 的车铲匹配结论（`N_j < S_j`、`N_max`、Σq_j ≥ P̃）给出**按班次目标固定的车组分配**：车 i 固定去装载点 g(i)，只在目标铲不可用（检修/排队超阈值）时溢出到次优铲。分配表在班前一次性确定，班内不重算。这是"最优但静态"的对照。

### B5 品位目标贪心（grade-targeting greedy）

```
score_j = |pred_grade_after(j) − target_grade(window)| − λ_prod·pred_throughput(j)
```
只做**当窗**品位校正，无跨窗前瞻、无承诺时点概念。用来证明"局部品位贪心 ≠ 班内 4 窗时序可行"。

### B2 班内滚动优化（intra-shift rolling）+ 兑现器

| 项 | 设定 |
|---|---|
| 重优化周期 T | 15 min（32 次/班） |
| 时域 H | 当前 2h 窗剩余时间（H ≤ 班末） |
| 决策变量 | `f[i][j] ≥ 0`：车 i 在 H 内派往装载点 j 的次数 |
| 车量约束 | `Σ_j f[i][j] = n_i(H)`，`n_i` 由名义循环时间估计 |
| 铲能力 | `Σ_i f[i][j] ≤ cap_j(H)` |
| 矿废量 | `Σ_j ore_j·q·f ≥ 目标矿量(H)`，废石同理 |
| 品位 | `Σ_j grade_j·q·f ∈ [lo,hi]·Σ q·f`，软约束 + 大罚松弛 |
| 目标 | `min Σ f·(ETA + queue·t_srv) + λ·Σslack`，λ=10 |
| 兑现器 | 每次决策取"剩余额度最大且合法"的 j；同额度按 ETA 决胜 |
| 求解器 | `scipy.optimize.linprog(method='highs')`（已装 scipy 1.15.3） |
| 计时 | 记录 `solve_time_ms`；RL 约 1–3 ms，B2 若 >50 ms 需在文中说明时延不可比 |

### B4 离线 oracle：三种口径，只有一种值得做

**先看配置事实**（nominal 独评，`phase_config.json` 实测）：装载点品位 **0.38 / 0.30 / 0.15**（废石 0.0），`gradeHalfRange=0.005`；破碎能力 **2500 tph**，但**缓冲仓只有 500 t**；4 个装载点 `shovelCapacity=1`、`singleServeTime=0.45 min`；车型 91.7/147/193 t 各 3 台；`grade band=[0.26,0.28]`、窗 7200 s、班目标矿 16,000 t / 废 4,000 t。

| 口径 | 内容 | 可行性 | 是否有意义 |
|---|---|---|---|
| **(a) 配比 LP**（忽略到达时刻） | 三档品位 0.15–0.38 的任意混合可覆盖整个区间，故 `[0.26,0.28]` 恒可行 | 现在就能算，分钟级 | **基本无意义**：它只能证明"不是配比配不出来" |
| **(b) 时序重排解**（含 500 t 缓冲 + 窗边界 FIFO） | 固定每趟的**观测到达时刻**，只重排"这趟来自哪个装载点/去哪一窗"，求最小品位偏差与最大合规窗数 | 1–2 天，纯离线，**0 仿真预算** | **推荐**：给"事后可达解"，报 `RL / hindsight` 比值 |
| **(c) 真·动态最优** | 决策序列与到达时刻同时优化（连续时间 + 随机服务） | **不可行**：状态空间爆炸，需 AnyLogic 在环做重放+局部搜索，且无法证明最优 | 不做 |

**结论：B4 定位为 (b) 事后时序重排解，不宣称"最优解"。** 关键约束是那个 **500 t 缓冲仓**——它只够 12 分钟的破碎量（2500 tph），所以"矿石落到哪个窗"取决于到达时刻而不是配比，这正是 C1（承诺兑现时点）的可量化落点。分析时必须显式建模：`buffer(t)` + FIFO 结算 + 窗边界。

不占预算、不改仿真。输出：`grade_feasible_windows_hindsight`、`min_deviation_hindsight`，配合 (a) 的"配比可行域"一起报告，说明"配比可行 ≠ 时序可行"。

## 4. 滚动规划 ↔ 当前方法的一一对应

| 维度 | B2 班内滚动 | 当前 BG128（RL） | 差异性质 |
|---|---|---|---|
| 决策时刻 | 周期 15 min，32 次/班 | **事件驱动**，实测约 177 次/班 | 粒度不同（RL 更细，B2 更粗） |
| 决策单位 | 流量 `f[i][j]`（9×4 矩阵） | 单车动作 `a ∈ {0,1,2,3}` | B2 需第二层兑现 |
| 约束处理 | 显式硬约束 + 松弛罚 | **动作掩码**只保证"合法装载点"，品位靠学习内化 | 硬 vs 软：这是核心区别 |
| 目标 | 等待代理 + λ·品位松弛 | 预注册标量联合成本（**实际结算**：wait + production + grade） | B2 优化代理，RL 优化结算值 |
| 信息 | 同一 1519D 快照的**聚合量**（ETA/队列/品位均值） | 同一快照 + 19 节点业务图 + C128 承诺摘要 | 信息量不同（RL 更多结构） |
| 品位反馈 | 每窗结算后重解 → 反馈延迟 **1 窗** | 窗结算进 reward，下一决策即可内化 | 反馈时延不同 |
| 兑现缝隙 | **有**：计划→动作需分配器 | **无**：直接输出动作 | **论文主张落点** |
| 求解时延 | 10–100 ms/次 | 1–3 ms/次 | RL 有部署优势 |

**这张表就是论文 §4 的骨架。** 关键论点不是"RL 比优化好"，而是：

> 滚动优化产出的是**流量计划**，落到单车仍需一层兑现器；这一层在每个决策时刻都重新猜"计划能否兑现"。BG128 的 C128 把"当前已承诺但未兑现 / 候选未承诺 / 已入仓已兑现"三态**编码进决策输入**，因此不需要兑现器。这就是 C1 claim 的可证伪形式。

对应地，B2 必须做**公平版本**：给它与 RL 相同的品位信息（C128 的 `grade_mean/std`、剩余矿废量）与相同的窗结算反馈，**只不给未来实测**。否则审稿人会判"基线被做弱"。

## 6. 预注册判据（先写死，跑完只填数）

- **主**：完整任务率（4 窗品位合规 + 矿废达产）
- **次**：累计等待车辆秒/班、每班 `grade_cost`、每班 ore 吨、`RL/oracle` 与 `B2/oracle` 效率比
- **统计**：全部在同一 100 班上逐班配对；RL vs B2 用 exact sign test（α=0.05）+ bootstrap 10,000 次 95% CI
- **论文 claim 三选一（按结果，不允许事后改判）**
  1. RL 完整任务率 ≥ B2 且等待显著更低 → "学习型调度在同等信息下优于班内滚动优化"
  2. RL 完整任务率 > B2 且等待持平 → "学习型调度扩张了品位可行域"
  3. RL 两端均不占优 → 诚实报告并转投方法学/工程期刊，不写 performance 卖点
- **禁止**：拿 B1/B5 的失败当主卖点（审稿人只认 B2）。
