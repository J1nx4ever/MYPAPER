# 矿岩联合配矿与调度：参数设计 V1

日期：2026-10-18。基础文件：DRL-PPO-31DV2(2).alp。
基础文件 SHA-256：d6154d62365c99a46f70274766174c2518c25a9e7a810918990523d7644d2a59。

本交付包含参数方案、前置连续LP与整车MILP筛查、复算代码。不修改原ALP，不进行训练。
这是有设备依据的合成实验场景，不代表任何实际矿山的标定数据。设备载重、备选铲斗来自制造商资料；储量、品位、路长、作业时间、速度和任务量为本方案的设计假设。

## 1. 最新业务边界

- 3个矿石装载点 HG1、HG2、LG，矿石全部送Crusher；1个岩石装载点WASTE，岩石全部送Dump（dumpNode）。
- 保留ALP路网拓扑和装载排队流程，不采用“三个停车位+道路溢出排队”的旧设想。
- 班次480 min；班前给定可用资源、储量和全局任务要求，不给各矿点固定供矿配额。
- 共享异质车队，RL在每次空车指派时选择装载点，矿岩属性决定卸载目的地。路线沿现有网络，不新增卸载目的地选择或中途改派动作。
- 矿点品位是均值，班内允许有界小幅波动。装上车后保持本车品位。
- 初始发车依照原状态图：同一驶出车道存在前车时，与前车距离达到30 m才允许进入下一指派状态；无前车的首车立即进入。30 m沿用ALP车辆位置参考点，表示放行阈值，不是固定时间间隔，也不重新解释为净车距。
- 破碎前有限缓冲，不作完全混合；按开始卸载顺序组织批次；卸载完成时整批进入缓冲。单卸载位保证先后顺序自然一致。
- 破碎完成量是成品产量；按四个固定2 h时间窗口统计吨位和金属量，不分成品仓。
- 岩石最低任务按Dump卸载完成量考核；班末在途、在卸载、未破碎的物料分别报告。

储量不等于必须完成的任务量。HG1较少是为了使有限高品位矿源具有机会成本；前置验算保证存在三矿源联合供矿方案，不给RL强加各矿点最低供矿量。三矿点品位均值沿用ALP，波动是新增场景机制。

品位过程：每个矿点按累计采出吨位划分500 t矿块，g(i,b)=均值(i)+U[-0.005,0.005]。0.005是0.5个百分点，不是均值的0.5%。一个episode、一个矿点有独立且固定的矿块序列。该分布的期望等于名义均值，单班有限储量的实现均值不强行校正回名义均值。

一车跨矿块时按各段实际吨位计算本车加权品位；装载开始确定本次取矿区间，完成时固化payloadGrade。不得在到达破碎站时重抽品位。状态可暴露当前工作面已知品位及长期均值，不能把尚未开采的完整随机序列泄露给策略。环境随机种子分流为地质、行驶和服务三组，避免动作次数改变同一段矿体的地质实现。

本版没有块体开采先后或“先剥岩再解锁矿石”的机理。最低剥岩量代表上层计划分解到本班的并行剥离任务。

选用4台Cat 6030 AC FS电驱液压正铲，每个点1台，班内不转场；不是把柴油6020称为电铲。矿点采用13.5 m³重岩斗，额定适用松散密度上限2.2 t/m³；岩石点采用15 m³重岩斗，额定适用上限2.0 t/m³。两种斗型都在制造商产品目录中；不将16.5 m³标准斗直接用于超出其目录适用密度的矿石。

装载时间参数为仿真假设：

- 充满系数0.90，单斗有效吨位q=min(30,斗容×松散密度×0.90)。矿石q=26.73 t，岩石q=27.00 t。
- 单斗循环27 s（0.45 min），对位及换车0.70 min。
- 斗数n=ceil(本车实际载重/q)，最后一斗允许部分装载，仍计完整单斗循环。
- 均值装载时间sL=0.70+0.45n；随机场景乘Triangular(0.9,1.0,1.1)。不把27 s声称为制造商保证的循环时间。

卸载服务时间含对位、举升卸料、降斗和驶离，随机场景同样乘三角分布因子。排队等待不计入服务时间。

矿量预约单独记录。派车时预留可供本车装载的吨位，装载完成时转为已采量，不能同时在两个回调重复扣减。允许储量不足额定载重时末车欠载，服务时间按实际斗数计算；前置整车见证解均使用满载，不依赖欠载凑数。

4台铲是在4个独立作业面持续可用的场景设定，不是经过设备购置成本优化证明的最经济台数。相同设备下首版不建模车辆故障或铲故障。

到另一个卸载点的距离用于卸载后跨矿岩任务的空车转移，不表示允许矿石去Dump。

自由速度=min(车型基础速度×路段乘数×扰动因子,路段限速)。主干限速30 km/h，矿点支路25 km/h。各车型速度差为本方案运行假设，未由厂家最高速度推导。

随机因子采用截断N(1,0.05²)，范围[0.85,1.10]，每个空载/重载行程各采一次；同一行程内不高频重抽。确定性验算统一取1。

保留ALP动态速度响应框架，更新0.2 s；加速度上限0.4 m/s²、减速度上限0.8 m/s²、jerk上限0.4 m/s³。跟驰期望参考点距离50 m；初始放行30 m是独立的起步条件，后车仍受跟驰制动约束。不能把50 m解释为起步时同样必须满足的硬最小间距，否则与用户30 m要求冲突。

同向禁止超车需要明确保持车道内顺序，不能仅凭连续速度响应就宣称已经保证。合流以实际到达合流点的时刻、同刻按固定车辆序号排序；暂不计交叉口异向路权延误。路段边界的跟驰关系需跨相邻路段连续维护。

道路平台宽度采用32 m展示假设（两向各12 m、中央隔离4 m、两侧余宽共4 m），只用于保证展示尺度容得下约8 m宽的大型矿卡；不宣称符合现场道路工程规范。ALP当前长度由network.getPathData计算，后续必须同步实际几何、比例尺和路径长度，不能只覆盖PathSegment.length。

## 5. 装载排队、发车与卸载破碎

装载排队保留ALP中的enterLoad→queueLoad→seize(shovelResource)→delay→releaseShovel→exitLoad；保留当前队列和资源获取机制，不额外建3个停车位，不增加道路排队回溢。每个资源池1台、每车占1台，Delay服务时间改为上表公式。队列等待与资源等待应统一统计，避免只数queueLoad遗漏seize中的等待。

ALP当前初始链条含：init1中的t.delay=i*10；Truck.transition8为state→branch的delay分钟超时；transition12为branch→NeedDispatchToLoadSite的1 min超时。目标实现沿用状态结构，移除用于初次发车的固定超时，以启动资格和同车道前车距离≥30 m进入NeedDispatchToLoadSite；不把30 m换算成固定秒数。普通卸载后的再次指派不应错误套用班初编号放行队列。

| 设施 | 设计值及规则 |
|---|---|
| Crusher卸载位 | 1个；serviceCapacity、dumpResource及Delay容量统一 |
| Dump卸载位 | 2个并行位，FIFO取得空闲位置 |
| 破碎前缓冲 | 500 t，初始为空 |
| 缓冲准入 | 空余吨位足以接收整车，开始卸载时预约本车吨位 |
| 容量守恒 | 实际存料+已预约未落料≤500 t |
| 入料 | 卸载完成后整批进入缓冲，预约量同时转为实际库存 |
| 物料顺序 | 开始卸载时间戳，同刻按卸载队列次序 |
| 处理能力 | 恒定2,500 t/h，即41.6667 t/min |
| 破碎机动作 | 从队首批次连续扣吨位，空缓冲时停料等待 |
| 品位变化 | 同一车辆批次的payloadGrade固定，不在缓冲内混合 |
| 窗口边界 | 跨120/240/360 min时按实际完成吨位切分批次并结算 |
| 成品仓 | 不建模 |

缓冲500 t约为2.59车最大载重或12 min额定处理量。单卸载位均值接收能力大于破碎能力，因而过度集中到矿可能产生容量等待；这必须由实际队列与缓冲机理产生，不能预先加一个固定“拥堵时间”。

班次从空系统启动。9辆空车位于ALP现有Crusher和Dump停车区域：3辆777在Dump，3辆785和3辆789在Crusher，按各驶出车道的30 m规则释放。这样首车即使承担岩石任务，也可由Crusher空驶到WASTE；前置运力计算已覆盖两种起点中较长的空车路线。

采用ALP已有[0,480)完成事件统计约定；恰好480 min完成的整车卸载不计本班，连续破碎积分至480 min。班后排空若执行，只作单独报告。固定窗口内无成品时不能判定品位合格，应标记无供矿；同时报告每窗吨位，不能用少供矿掩盖问题。

## 6. 前置数学模型及证明边界

变量x[w,i,k]≥0为窗口w分配给点i、车型k的车次当量；MILP时x为非负整数。p[k]为载重，g[i]为矿点均值，sL、sD为服务时间。

循环时间τ[i,k]=max(Crusher至i空车时间,Dump至i空车时间)+i至合法卸点重车时间+sL[i,k]+sD[i,k]+1 min。

额外1 min是前置筛查中为起停等保留的时间额度，不在ALP速度积分之外再次添加一个重复Delay。它不保证完全覆盖交通和排队延误。

| 点位 | 777循环/min | 785循环/min | 789循环/min |
|---|---:|---:|---:|
| HG1 | 17.390 | 19.687 | 22.354 |
| HG2 | 23.405 | 26.298 | 29.695 |
| LG | 21.046 | 23.706 | 26.816 |
| WASTE | 15.869 | 18.017 | 20.493 |

这些是较长空车起点下的名义循环时间（含1 min额度），不是已经观测到的实际平均循环时间，也不是最坏情况上界。

主要约束：

1. 储量：sum(w,k) p[k]x[w,i,k] ≤ R[i]。
2. 车型时间：sum(i) τ[i,k]x[w,i,k] ≤ N[k]×H_eff[w]×0.90。
3. 装载时间：sum(k)sL[i,k]x[w,i,k] ≤ m[i]×H_eff[w]×0.90。
4. 卸载时间：分别对Crusher和Dump限制总卸载服务工作量，乘以各自卸载位数。
5. 处理量：sum(i属于矿石,k)p[k]x[w,i,k] ≤ 2,500×H_eff[w]/60。
6. 品位：G_low×T[w] ≤ sum(i属于矿石,k)g[i]p[k]x[w,i,k] ≤ G_high×T[w]。
7. 班次供矿≥16,000 t，岩石≥4,000 t。

为展示更强的见证解，附带每窗矿石LP恰好4,000 t、整数解4,000—4,100 t；岩石LP恰好1,000 t、整数解1,000—1,200 t。这些均匀分配只是见证解附加条件，不是对RL新增的四个固定剥岩配额。

H_eff=[100,120,120,120] min，首窗先扣20 min冷启动额度，资源工作时间再保留10%余量。LP每窗均值品位设为27%；MILP收窄为26.9%—27.1%。有界波动下，任意既定吨位组合的实际品位偏离其均值组合不超过0.5个百分点。

注意：x的窗口分配没有显式表达车辆事件、真实流转时间、库存跨窗和FIFO批次处理。装载/运输工作量与该窗口成品量被汇总关联，因此该模型证明的是“所列汇总条件下的可行分配”，不能证明存在满足全部ALP动态机制的车辆时刻表。首窗20 min与10%余量是设计额度，不能把它们当作动态可行性的数学替代。

| 观测、日志与训练接口 | 异质载重、矿量预约、当前品位、缓冲、已承诺矿岩吨位需要新契约；原31D和旧训练权重不能直接声称兼容 |

此处列出变更范围，不在本轮选择PPO损失、奖励权重或乘子参数。业务硬要求不等于奖励惩罚能够逐班保证，后续必须独立报告矿石任务、岩石任务及窗口品位的达标率。

## 9. 下一层验证要求

将参数写入ALP后，先跑确定性规则调度，核查质量守恒、资源占用、真实初次放行时间、道路距离和四窗输出；再做随机重复实验。只有取得按车辆事件排列的可执行时序，并通过500 t缓冲与FIFO破碎检查，才可升级结论为“动态场景存在可执行的合格调度”。随机品位不会因这里的LP可行就保证RL达标。
